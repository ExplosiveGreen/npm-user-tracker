## Findings

### MISSING_INSTRUCTION (new)
- TanStack DB's React Native persistence adapter (`@tanstack/react-native-db-sqlite-persistence`) is built **only** on `@op-engineering/op-sqlite`; there is no Expo-SQLite adapter. User asked for "expo sqlite", so the substitution needed an explanation. The adapter's peer range (`op-sqlite ^15.2.5`) is stale vs. what Expo SDK 57 / RN 0.86 new-arch needs (op-sqlite 17), so we installed 17 and the peer warning is expected — document this so we don't "fix" it later.
  - **Fix for future**: state library-imposed constraints up front when the user's requested package name doesn't match the supported path.

### INEFFICIENCY
- TanStack DB 0.6 has almost no public docs for the RN persistence path; correctness was established by reading the installed package `.d.ts`/`.js` (overloads for `useLiveQuery`, `persistedCollectionOptions` shape, `OpSQLiteDriver` execute-method selection, `Collection` generic arity). Reading shipped type defs beat guessing.
  - **Fix for future**: for alpha-tier libs, inspect `node_modules/.../dist/esm/*.d.ts` directly instead of searching docs.

### WRONG_BEHAVIOR
- First attempt at the op-sqlite DB adapter object passed the raw `database` and used `executeAsync`; op-sqlite 17 renamed to `execute`/`executeSync` and its `params` is `Scalar[]` (mutable), so a small wrapper object was required to satisfy `OpSQLiteDatabaseLike`. Also wrongly added `@op-engineering/op-sqlite` to `app.json` plugins — the package ships no config plugin (autolinked), which broke `expo config`.
  - **Fix for future**: check whether a lib ships a config plugin subpath before adding it to `app.json` plugins.
