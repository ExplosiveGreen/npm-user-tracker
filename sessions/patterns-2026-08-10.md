# Patterns — 2026-08-10

Session: add a Delete button + confirmation to the DB explorer table screen, with an E2E flow, then run the full verify gate (typecheck, expo-doctor, maestro e2e on an Android emulator).

## Summary

- First pass added `getKey` to every `DbTable` registry entry in `db/index.ts`; the user pointed out this was unnecessary — every row already carries its primary key inside it as TanStack DB's virtual `$key` prop (the same value the collection derives via its `getKey` config). Reverted the registry additions; `app/db/[tableName].tsx` now reads `String(item.$key)` directly.
- `app/db/[tableName].tsx`: `Delete` button (testID `delete-row`) per row card, Alert confirm, then `collection.delete(key)`; card React key switched from index to `item.$key`; TanStack's `$`-prefixed virtual metadata (`$key`/`$synced`/`$origin`/`$collectionId`) filtered out of the rendered row content.
- New `.maestro/table-delete.yaml` populated by `online-retry.yaml` data: navigate to `npm_users`, tap Delete, confirm, assert the row disappears. Wired into `scripts/e2e.mjs`.
- First pass used hardcoded `point:` taps in the theme flows; the user flagged this as fragile (coordinate interactions break with future layout changes). Reverted to `tapOn: id: dark-mode-switch` everywhere; the dev-menu self-healing repeat now presses by testID.
- Verified after the rework: `pnpm typecheck` (0), `expo-doctor` 20/20, full maestro suite green.

## Findings

### WRONG_BEHAVIOR — infra I killed that I didn't start
- The environment already had a working emulator on port 5554; my `emulator -avd e2e` start attempts were failing all along (`FATAL` — the `e2e` AVD pointed at a nonexistent `android-35` image, while the SDK only ships `android-36`). I only noticed after `pkill -9 qemu-system` killed the working pre-provisioned emulator. Lesson: check what's already talking to `adb` before starting/killing emulators, and read the emulator log's startup lines before trusting an AVD config.

### REPEATED_PATTERN — pkill self-matching
- `pkill -f nativewind` matched the shell's own command line (`bash -c '... nativewind ...'`), killing the shell that ran it → two 120s tool timeouts. Same class of footgun as broad `kill` patterns. Fix for future: use exact binary/PID scoped kills (e.g. `pgrep -f` then give explicit PIDs, or match the enclosing binary path rather than a keyword that appears in my own command).

### INEFFICIENCY — E2E fell into env-specific Expo Go behavior
- On a fresh-launched Expo Go, Maestro's first switch interaction pops the React Native dev menu over the app (reproducible on this emulator; `adb shell input tap` and "warm" interactions don't). Diagnosed via probes (element tap vs point tap vs warm-up tap). Shipping fix is in the Maestro flows, not app code: tap, dismiss the dev menu if it appears, and repeat until the expected theme label shows. App logic was verified correct independently.

### REPEATED_PATTERN (from 2026-08-09)
- Again the value of inspecting the *running environment* over trusting docs/assumptions: the AVD config, the pre-provisioned emulator, and Maestro's actual tap semantics were all ground truth. Consistent with prior sessions' finding about reading shipped/runtime truth. Already the AGENTS.md default; no change.

### WRONG_BEHAVIOR — over-engineered instead of checking the domain type
- I added a per-registry `getKey` to the `DbTable` type before checking what a row actually exposes. The user corrected me: every item already has its key inside it (TanStack DB's virtual `$key`, confirmed in the rendered row output). I should have inspected the item shape (or the library's `WithVirtualProps` type) before adding a whole registry surface. Cost: a full revert of `db/index.ts` plus another verification pass.

### WRONG_BEHAVIOR — hardcoded coordinate taps in E2E
- I shipped `tapOn: point: "940,401"` in the theme flows to dodge Expo Go's dev-menu pop. The user correctly rejected coordinate interactions: they silently break on any layout/resolution change. Reverted to `id:`-based presses. Lesson: selectors must be semantic (testID/text), never viewport coordinates.

### REPEATED_PATTERN (from 2026-08-09)
- "Read the shipped/runtime truth before building abstractions" recurs for the third session in a row (types, then runtime behavior, now row properties). The `$key` discovery was in the installed `.d.cts` (`WithVirtualProps`) and confirmed at runtime in the rendered hierarchy — both available before I added the registry function.

## Recommendations

- Consider a small skill or AGENTS.md note: "Before touching emulator/adb infra, run `adb devices` + read the emulator start log" to avoid killing pre-provisioned environment resources.
- Optionally: the `e2e` AVD image path is still wrong-on-disk (`android-35` referenced, `android-36` present); the environment fix I applied (repoint to `android-36`) is not committed anywhere.
