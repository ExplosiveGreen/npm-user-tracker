# Patterns 2026-10-06 — notifications release + first local APK

## MISSING_INSTRUCTION
- Expo managed workflow + pnpm: `babel-preset-expo` and friends must be direct
  deps. pnpm strictness hides them (npm hoists). Missing ones only surface in
  release/dev bundling, NOT in `tsc` or `expo-doctor`. Candidates to always
  keep direct: `babel-preset-expo`, `@babel/plugin-transform-react-jsx`,
  `@babel/preset-typescript`.
- Version skew inside one major breaks silently: `@babel/*@8` installed next to
  `@babel/core@7` doesn't error — TS stripping just stops working. Pin same
  major as `@babel/core`.
- `react-native-worklets` bundle mode REQUIRES the official metro patch
  (short-circuits `getOrComputeSha1` for `.worklets` files). Without it every
  release/dev bundle fails. Patch source:
  `software-mansion/react-native-reanimated/.../bundleMode/patches`. Applied
  via `pnpm patch` → `patches/metro@<ver>.patch`, recorded in
  `pnpm-workspace.yaml:patchedDependencies`.
- The worklets plugin `writeFileSync`s into `node_modules/.../.worklets/`
  without mkdir. Never `rm -rf` that dir (only stale `*.js` if ever); added a
  `postinstall` guard that recreates it.
- `.worklets/*.js` + Metro transform cache are coupled state: wiping one
  without the other gives ENOENT. Clear both (`/tmp/metro-cache`,
  `/tmp/metro-file-map-*`, `android/build`, `android/app/build`) together.

## WRONG_BEHAVIOR (fixed)
- `latestJobByUser` kept the FIRST scan per user instead of latest (map set
  without newest-first ordering). Fixed with newest-first + set-if-absent.
- Release `signingConfig signingConfigs.debug` shipped in generated
  `android/app/build.gradle`. Local release builds need a real keystore;
  created `~/.keystores/npm-user-tracker-release.jks` (PKCS12: key password
  MUST equal store password). Back it up — updates require the same key.
- `gh` CLI spins CPU and hangs in this env (network OK via curl). Used
  `curl` + token from `~/.config/gh/hosts.yml` for PR merge/release API.

## INEFFICIENCY
- 11 gradle runs to first APK. Each failure class needed a full rebuild to
  surface the next one. A fast loop (`expo export -p android`, ~1 min)
  reproduces JS-bundling failures without gradle — should have switched to
  it after failure #2.
- pnpm `public-hoist-pattern` / `.npmrc node-linker` were dead ends:
  `.npmrc` is ignored here, and direct deps stay symlinked regardless.
  `pnpm-workspace.yaml: nodeLinker: hoisted` is what works.

## Follow-ups (not done)
- `metro-runtime` fast-refresh patch (dev-only nicety) skipped.
- `gh` CLI hang root cause unknown.
- EAS cloud build not set up (no EXPO_TOKEN); releases use local gradle
  builds + API upload. Release keystore lives only on this machine.

## Effect 4 notes (alpha 2)
- `latest` tag is 4.0.1 stable — always check dist-tags, memory of "v3 latest"
  goes stale fast.
- v4 removed `catchAll`/`orElse`/`fold`/`either`. Recovery = `matchEffect({
  onFailure, onSuccess })`, `orElseSucceed`, `match`. `catchTag`/`mapError`/
  `tapError` still exist.
- v4 `Schema.Union` takes an array: `Union([A, B])`, not variadic.
- v4 decode of `unknown` JSON: `Schema.decodeEffect(schema)(input as typeof
  S.Encoded)` — cast satisfies input type, decoder still validates at runtime.
- `Effect.promise`/`Effect.sync` are infallible-typed (failures are defects);
  use `tryPromise({ try, catch })` for typed errors. Its thunk receives an
  AbortSignal — pass to fetch for free cancellation + timeouts.
- Retry with cap+delay: `Schedule.recurs(n).pipe(Schedule.addDelay(() =>
  Effect.succeed("<duration>" as const)))`. No `intersect` in v4 Schedule.
- `Schema.Record(Key, Value)` is a function, not a const.
- Scoping call: Effect went into registry I/O + scan orchestration +
  notifications (lib/script.ts, lib/registry-schema.ts, lib/notifications.ts).
  Deliberately NOT in prefs.ts (sync), db cascade (order-sensitive),
  tasks.ts registration glue, or React components (promises fit there).

# Patterns 2026-10-06 (evening) — username autocomplete + alpha.4

## INEFFICIENCY
- Spent ~35 registry probes learning that /-/v1/search ranks by relevance
  with no match-all/popularity-sort: prefix maintainer queries always return 0
  (exact/wildcard/plain/npms.io all verified), and relevance sampling misses
  mid-tier maintainers no matter the query. Should have tested ONE exact vs
  prefix pair (t3dot vs t3dotgg) and stopped theorizing.
- Drove headless chromium over CDP to spy on npmjs.com typing; Page.navigate
  hung on Cloudflare. The answer (GET /search/suggestions?q=, 400ms debounce,
  packages-only) came faster from grepping their static JS bundle. Prefer
  static bundle analysis over driving browsers behind bot walls.
- `gh` hangs even on `--version` in this env; the known workaround (curl +
  token from ~/.config/gh/hosts.yml) still works — used it for PR creation.

## WRONG_BEHAVIOR (fixed)
- Ranking maintainers by download sums double-counted packages matching
  several sample queries. Dedupe packages by name across caches before
  aggregating.
- bun install rewrote package.json (patchedDependencies) and added bun.lock
  in a pnpm repo. Reverted; install with bun only for local verification,
  never commit its side effects.
- Dropped `PAGE_SIZE` const during a script edit; runtime caught it. Re-run
  generator scripts after every edit, they are cheap (cache is gitignored).

## MISSING_INSTRUCTION (candidate)
- No public npm API does username prefix search (registry/npms.io exact-only,
  npmjs suggestions packages-only + Cloudflare-walled). Autocomplete must
  ship its own prefix index: build-time snapshot + in-memory scan.
