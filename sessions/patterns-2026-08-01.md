# Patterns — 2026-08-01

Session: debugging Expo SDK 57 crash in `npm-user-tracker-fresh` (drizzle-orm + expo-sqlite) on x86_64 emulator.

## Summary

- Root cause isolated: `react-native-reanimated`/`react-native-worklets` native runtime crashes Hermes V1 on x86_64 emulators (not app code).
- Proved via isolation: vanilla `create-expo-app` blank app + reanimated import = byte-identical crash; vanilla alone = stable.
- Verified full app + migrations on emulator by temporarily stubbing reanimated/worklets via metro `resolveRequest`.
- Migrations confirmed working (full schema rendered from live SQLite).

## Findings

### MISSING_INSTRUCTION
- Background long-running processes (metro dev server) started via `nohup bunx ... &` in a bash tool call **die when the shell tool times out**. Needed `setsid ... < /dev/null & disown` to keep them alive across the 120s shell timeout. Wasted a restart cycle on this.
  - **Fix for future**: always start background dev servers with `setsid nohup ... < /dev/null & disown` in one shot.

### INEFFICIENCY
- Screenshot capture + image read for verifying emulator UI: model can't read images. Should have gone straight to `uiautomator dump` + grep of `text=` / `bounds=` from the start.
  - **Fix for future**: verify emulator UI via `adb shell uiautomator dump` text output, not `screencap`.

### INEFFICIENCY
- First verification bundle request returned HTTP 000 because the metro process had died silently (see MISSING_INSTRUCTION). Spent one failed curl round before checking `ps`/log.
  - **Fix for future**: check server `ps` + `curl /status` before requesting a bundle.

### WRONG_BEHAVIOR
- Tapped blind coordinates to dismiss the Expo Go first-launch dev menu; it re-opened the dev menu (Continue button). Correct approach: read bounds from `uiautomator dump` first, tap the real control, use `keyevent 4` (BACK) to dismiss dev menu overlays.
  - **Fix for future**: always parse bounds from uiautomator dump before tapping; BACK closes the dev menu.

## Recommendations

- Nothing to add to AGENTS.md for app code. Consider a small operational note: "Emulator UI verification = uiautomator dump text, never screencap. Background servers need setsid+disown." — optional, low priority.
- The reanimated/worklets x86_64-emulator crash is a known upstream class (hermes#1873); no code change needed. If user repeats this, create a skill: "React Native crash with no JS error on x86_64 Android emulator → suspect reanimated/worklets, isolate with vanilla repro, verify via metro stub."

Audit found 0 repeats from previous sessions, 1 MISSING_INSTRUCTION, 2 INEFFICIENCY, 1 WRONG_BEHAVIOR. No lasting issues; stub is uncommitted and revertable.
